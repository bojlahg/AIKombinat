## Hook verification evidence

The hook initially reported `not_installed`. AIKombinat installed it as `installed_unverified` with a copied bridge and a launcher pointing at this server's Node runtime. The first real telemetry Todo made a Claude `Read` but produced no observation: on Windows, the old managed definition placed a `.cmd` launcher in an exec-form hook (`args` present), which Claude cannot spawn as an executable. After the fix and reinstall, the definition hash changed from `17e8b217…` to `d77df207c1f38ea2c360f4733775f93475a0684c53f72c8a75af73b1ebbaa0c0`. A subsequent real Claude `Read` produced an observation with that exact hash, and status changed to `verified`. No internal hook HTTP request was used to produce verification. The status check also confirmed the launcher, expected Node runtime, bridge path, and copied bridge SHA-256. The automated installer test confirms that an old observation cannot verify a new installation and that a corrupted bridge copy becomes incompatible.

The telemetry observation stored `Read`, `read_file`, `large-service.ts`, 53,793 bytes, null offset/limit, `allow/telemetry_only`, 1 ms hook latency, and the current definition hash. The observation table has no source-content, prompt, environment, or raw-command columns. A real Bash observation from the capacity-holder Todo stored only command kind `node`, raw length 38, and a 64-character SHA-256 hash; the command text was absent. The actual telemetry database was inspected for these fields, not just the API aggregate.

## Isolation evidence

The real `bulk_read` calls launched Claude Haiku workers and returned schema-validated ranges. The worker launch path uses a disposable scratch directory, passes source only in the prompt, sets depth 1, disables built-in tools with `--tools ""`, disables filesystem setting sources, and supplies an empty worker-only strict MCP configuration. The primary MCP configuration remains additive. The adversarial source strings did not produce any observed file or tool action; the harmless outside canary stayed unchanged. The real process command line and worker-internal tool registry were not captured independently, so this combines observed worker execution with adapter configuration and regression tests rather than claiming an OS-level proof that no tools were offered.

Codex, Antigravity, and `raw-shell` were not used as workers. The existing eligibility tests cover their unsupported/invalid status and depth-based recursion prevention. Sensitive, traversal, symlink, bounds, range-merge, and stale-SHA checks remain covered by the delegation test suite.

## Lifecycle evidence

The final successful worker run recorded `running` with PID `10112` and a non-null creation-time identity, then `completed` with PID and identity cleared. The controlled Stop separately captured worker PID `46996` and a non-null identity while `running`. Stop attempted SIGTERM and SIGKILL for both worker and primary. Windows did not confirm termination within the deadlines, so the worker retained `recovery_required`, PID, identity, and capacity ownership; the Stop endpoint returned 500 instead of force-clearing ownership. Both processes subsequently exited, and passive recovery cleared the worker PID and identity, released capacity, and left the Todo stopped. The deterministic stale-file integration test changes the source between initial SHA and worker result and confirms `stale` with no old ranges; a live stale race was not reproduced.

## Bugs found and fixed

| Symptom | Root cause | Fix | Regression/evidence |
|---|---|---|---|
| Real Claude `Read` produced no hook observation on Windows | Managed `.cmd` launcher used exec-form `args`, but Claude requires a shell for `.cmd`/`.bat` hooks | Use an explicit PowerShell shell-form command on Windows and bump managed schema/hash | Installer test executes the installed hook command; real telemetry observation verified the new definition. |
| Successful worker launch was interrupted by passive recovery | Recovery treated every persisted live PID as an orphan, including one still tracked by this server | Passive recovery skips a live worker still owned by `ClaudeManager`, after dead/mismatched identity checks | Regression test covers active then orphaned worker; real suggest retry completed. |
| Worker identity was null on this Windows host | CIM process probe returned no row in this environment | Read process creation time with `Get-Process` | Real self-probe returned a matching identity; cancellation run persisted worker PID and identity. |

## Remaining limitations

1. Suggest guidance did not induce delegation after the full file had already entered primary context. Its response-character metric alone cannot be counted as realized savings.
2. More than one worker result pointed to data rows instead of the named function definitions (narrow lookup, suggest retry, and lifecycle run). Primary recovered with Grep or extra targeted reads. The two-region enforce run returned the correct ranges. Worker relevance needs a broader quality sample, and no worker prompt was changed to fit this fixture.
3. A suggest worker success did not finish its parent Todo because the primary spent turns on wrong path attempts. The successful two-region enforce run used a 15-turn limit.
4. Service-down fail-open was not reproduced during a normal Todo because stopping this local AIKombinat server also stops its owned Todo processes. A bridge-level regression runs against an unreachable loopback endpoint and confirms exit 0 with no denial output. A real stale-file race was not reproduced; stale SHA has deterministic integration coverage.
5. Controlled Stop exercised unresolved retention and eventual passive release, not an immediate confirmed-termination branch. The OS-level worker tool registry and command line were not captured.
6. Worker input tokens and latency are real. Primary token savings, total cost benefit, and a statistically useful fallback rate remain unknown after this small fixture sample.

## Validation

`npm run typecheck`, `npm test`, and `npm run build` passed. The full test run reported 935 passing and 1 skipped server tests, plus 165 passing client tests. The schema was unchanged, so no migration or ERD regeneration was needed. `git diff --check` found no whitespace errors.

## Conclusion

**READY_WITH_LIMITATIONS.** The real Todo → Claude hook → MCP → Claude worker → validated ranges → targeted primary Read path completed, and enforce mode avoided full source reads in the A and B runs. The observed response-character reduction was about 51 thousand characters per successful matching run. Several worker range misses, suggest-mode non-adoption, and Windows Stop timing limits prevent a general cost or quality claim. Expand measurement with varied real repositories before wider rollout.
