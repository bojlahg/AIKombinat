# Whole-treatment usage accounting V1

Ordinary provider processes finalize nullable `attempt_wall_duration_ms`, `provider_duration_ms`, `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens` and `cost_usd` on their own `todo_execution_rounds` row. Capture runs after stream drainage and before cancellation, failure, quota failover or pipeline advancement. Stream usage is keyed by the round run token so a late callback cannot consume a later attempt's telemetry. Finalization sets fields, never adds them; omitted/invalid telemetry cannot erase previously known values. Recovery does not fabricate usage.

Consensus reviewer and judge usage remains in `consensus_review_attempts`, including nullable cache fields. The collector flushes the trailing result line before persisting usage. A Consensus coordinating review round is excluded from the ordinary process denominator: the batch's started reviewer/judge attempts supply the canonical process usage.

`getTodoTreatmentUsage` derives content-free totals and phase summaries from all started attempts regardless of status. Waiting rows with no `started_at` are excluded. Cost is provider-reported only. I/O tokens require both input and output telemetry and mean their sum, excluding cache. Every metric has its own known/started attempt counts and coverage; zero attempts yield null known value and null coverage, while provider-reported zero is known. Cache read, cache creation and local process wall duration and provider-reported duration remain separate. Todo wall-clock duration retains time between attempts, including human waiting.

Campaign analytics uses one scoped SQL aggregation for all campaign Todos; assignment/CSV reads scope aggregation to the requested page. No per-assignment usage queries, treatment cache or new indexes are introduced. All attrition/ITT/PP populations retain their existing membership rules. Partial sums are visible with attempt coverage; only fully covered started Todos enter average/P50 treatment cost. Comparisons use these per-Todo statistics with population N and coverage, without rankings or winners.

Assignment API/CSV adds `known_treatment_cost_usd`, cost attempt counts/coverage, `known_treatment_io_tokens`, token attempt counts/coverage, separate cache fields/coverage, process attempts and known provider duration/coverage. Assignment JSON also exposes the five phase summaries. Existing `known_todo_*` assignment fields and `knownTodo*` arm fields are deprecated latest-process compatibility values, not treatment evidence. The UI and arm comparisons use only the new treatment fields. Legacy `todos.token_usage`, `todos.total_cost_usd` and `todos.total_tokens` keep their existing meaning.

Migrations add nullable fields idempotently and preserve foreign keys. Code archaeology (`69f5bbf`, the commit introducing ordinary round duration capture) confirms ordinary legacy `duration_ms` was populated exclusively from provider result telemetry: migration copies valid legacy ordinary duration to `provider_duration_ms`. Consensus legacy duration was local elapsed: migration copies it only to `attempt_wall_duration_ms`, never to provider duration. Backfill runs when the canonical column is first added and never overwrites explicit values on repeated startup. No backfill from ambiguous Todo totals occurs. Lower historical coverage is expected.

The deterministic DB regression reproduces `$0.0426689 + $0.0356593 + $0.0566660 + $0.0176279 = $0.1526221`, with four process attempts and 4/4 cost coverage. The latest-process `$0.0356593` remains available only as the deprecated compatibility value. Tests also exercise process success/failure/stop, retry/failover isolation, Single Review/rework, Consensus retries/judges, partial/zero/unknown telemetry, migrations and campaign/UI exports.

Evaluation Campaigns V1 remains READY; the Real-World Dogfooding Pilot V1 remains NOT_STARTED. Before real enrollment, freeze an explicit sensible implementation max-turn setting identical across arms. Synthetic setup and retry evidence remain outside the real-world sample. No global execution default or routing behavior changes.

Duration semantics: Todo wall-clock remains assignment.first_execution_at → assignment.finished_at and can include quota/executor waits, review/rework, human pause and manual retry delay. Process wall-clock (attemptWallDuration) is locally observed attempt runtime, independently of provider telemetry. Provider-reported duration (providerDuration) is available only when the provider reports it. Both metrics expose known sums, started-attempt counts and coverage in every phase and attrition/ITT/PP population. Waiting attempts with no start are excluded; invalid negative/nonfinite values are ignored and known zero is retained. Failures, stops and recovery preserve observable wall time without fabricating provider duration.

For example, implementation 10s + human wait 30m + retry 10s gives Todo wall-clock ≈ 30m20s and summed process wall time ≈ 20s.

The compatibility column duration_ms is deprecated: ordinary aliases provider_duration_ms; Consensus aliases attempt_wall_duration_ms. Canonical treatment aggregates never read this mixed legacy column. API/CSV exposes known_attempt_wall_duration_ms, attempt_wall_duration_attempts_known/total/coverage and known_provider_duration_ms, provider_duration_attempts_known/total/coverage. Arm metrics expose the equivalent camelCase fields.
